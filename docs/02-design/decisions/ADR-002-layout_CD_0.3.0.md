# 完整工作方式与运行资产隔离决策

> 版本: 0.3.0 | 创建: 2026-10-09 | 状态: active
> 关联: [[FILE_INDEX|文件索引]]

## 依据与候选

用户认为0.2.0工作目录仍混乱，并要求看完整engineering模式。现有src布局不足以满足真实工作目录、七阶段、全文件索引和交接。候选：继续让运行数据散落根目录；统一.local并移动工具；移动整个frameworks下仓库并重建所有环境。选择第二项：能解决项目现场问题，范围可逆，不破坏其他独立服务。

## 决策与影响

运行数据统一STATE默认.local，配置/.env先读STATE并兼容旧根文件；新安装写.local。工具入口从根移scripts，保留system1.sh/ps1唯一日常入口；之前A1/A2是实现者假设，用户返工要求优先，更新对应实际行为。迁移清单和原配置在私有目录保留。

虚拟环境与CMake产物含绝对路径，直接移动会破坏shebang/cache/RPATH，因此保留隐藏.venv*和.native-build，明确为工具目录，不把它们当交付制品。产品库用版本化.local/products和SHA256满足小团队三库降档；从验证标签构建，不直接用开发区文件当发布依据。

工程模式persona的宿主专属工具不复制进服务；本仓落地七阶段、关口、原话、范围、计划、事实分离、索引、真实测试和交接。已有用户授权继续有效，不为同一动作重复请示；不能声称用户已批准实现者自拟验收。规范快照保持原字节，当前流程见PP。

## 架构原则与检查

保持配置单一真源；运行资产与代码分离；依赖最小；Jev契约稳定；进程身份和回退优先。没有新中间件/第三方依赖。模块风险与生命周期不变，仅将配置路径边界集中common，工具和运行数据按生命周期隔离；下游CLI、子进程、CI、文档同步更新。

## 后果

根目录不再暴露模型/日志/证据和散列Python命令；用户改用scripts路径。代价是一次相对路径迁移，以及隐藏位置绑定工具仍保留。coverage与目标laptop欠账不随目录整理消失。
