# 工程规范适配决策

> 版本: 0.2.0 | 状态: Active
> 适用范围: System1 Ops
> 关联: [[FILE_INDEX|全库索引]]

## 背景与决定

用户要求按dsh-agent-presets engineering规范组织已可用的Linux CUDA和Windows CPU项目。规范快照固定至74dfcd1270675713853c5f87e798ed9b5f7acb25，见standards/source.json；源文件逐字保留并附Apache许可。

选择src包布局与uv服务/开发工具锁；保留公开CLI桥接，私有运行文件不迁移。备选是维持根目录平铺，或彻底切断旧CLI并统一新命令；前者不便维护，后者会破坏已交付操作方式。

## 适用范围与明确裁剪

| 条款 | 本项目处理 | 理由、边界和回退 |
|---|---|---|
| Python依赖锁定 | uv.lock锁HTTP/开发依赖；模型源提交固定、安装索引和版本约束记录 | torch CPU/CUDA不同构建，硬塞进单一服务锁会重复下载大包；模型环境由setup-runtime维护，版本写测试证据 |
| pydantic-settings配置 | 保留TOML + 两个认证环境键的白名单.env解析 | 已交付的逐模型解释器和相对路径规则；仅解析键值且不执行shell。新配置须common校验，真实CLI验证 |
| 默认所有入口鉴权 | 管理接口fail-closed；模型API空key保留可选匿名模式；健康端点公开 | 保持现有Jev客户端兼容，限定可信网络。对外代理/不可信网络配置API key与TLS；不得以本裁剪称生产安全全通过 |
| TLS/过期token/租户配额 | 本服务不实现公网TLS终止和多租户会话 | 当前是单机推理维护；交由部署入口控制，扩展公网产品时重新评审 |
| 严格类型 | 包内所有公共函数标注、mypy检查函数体；动态模型对象/JSON采用Any边界 | 三类上游对象签名不统一；不声称零Any或全量strict；保持具体配置返回类型和设备空值检查 |
| 核心覆盖率建议70–80% | 当前全包单测分支覆盖约37%，自动门槛35%；真实模型/平台集成独立必测 | 低于建议值，主要缺口为硬件/CLI/原生加载路径；不靠mock刷高覆盖。发布需真实HTTP、native与Windows smoke；覆盖阈值可随有效用例提高 |
| DB/消息队列/迁移DDL规范 | 不适用 | 没有数据库、持久消息或数据表；不引入空架构 |
| 所有规范文件frontmatter/index | 项目正式文档严格检查；引入规范逐字/hash校验 | 上游标准包含示例与自身格式，避免为了本仓改写成第二真源 |
| 小函数原则 | 各文件按职责归属；既有Engine/CLI流程保留 | 避免目录整理夹带推理重写；格式化拉长的已有动态加载函数作为明确后续拆分项 |
| 物理三库/交付周期/DORA | 特性分支、验证标签、源码归档校验和；CI强制门禁 | 单维护人无组织流水线数据，未采DORA不编数字；硬件重型集成采用手动CI |

## 授权与回退

当前目录重构为N级可回退变更，授权来源是用户本轮明确整理指令及持续维护/测试/公开推送授权。Git基线baseline/pre-engineering-fd8ada3。失败条件：质量门禁失败、API契约差异或原服务无法恢复；保持修改在特性分支，通过worktree检出基线运行入口、同私有配置启动可回退。未经验证不删除缓存或改8881状态。

## 后果

优点是标准来源可追溯、跨平台检查统一、旧客户端兼容。代价是少量入口桥接、模型环境独立锁定边界、明确的覆盖和大函数欠账。[[03-plan/tasks]]跟踪欠账，[[05-testing/FTR-system1_VD_0.3.0]]记录验收。
