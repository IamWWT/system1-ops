# 可靠性规范

> 目标：服务在故障、流量高峰、并发竞争下不丢数据、不卡死、不雪崩。

## 1. 超时与重试

| 规则 | 说明 |
|------|------|
| 所有外部调用有超时 | HTTP/DB/Redis/消息：显式超时，禁止无限等待 |
| 重试有界 + 退避 | 最多 2-3 次；指数退避 + 抖动；记录重试次数 |
| 重试要幂等 | 重试前确认操作可重复执行（见 §2） |
| 上游熔断 | 依赖故障率超阈值打开熔断，快速失败 + 半开探测 |

## 2. 幂等与并发 ★

| 规则 | 说明 |
|------|------|
| 消息消费幂等 | 唯一 messageId/业务 key 去重；消费后结果可重复应用 |
| 状态变更 CAS | `UPDATE ... WHERE state=期望值`，禁止裸覆盖；失败明确报错 |
| 并发写有保护 | 乐观锁/版本号/唯一约束；禁止"最后写入覆盖"导致数据丢失 |
| 单真源矩阵 | 状态机转移矩阵只存一处，禁止副本漂移 |

## 3. 失败处理

| 规则 | 说明 |
|------|------|
| 禁止吞异常 | catch 后必须处理或记录并明确降级 |
| 显式降级（fail-soft） | 可选能力失败时降级（如缓存不可用直接查库），但要打日志 + 有兜底 |
| 死信处理 | 消息重试耗尽后进死信/落盘，可重放；禁止静默丢弃 |
| 卡死兜底 | 状态机/子流程必须有终态兜底（有限重试后升级/收尾），禁止永久等待 |
| 空回复防护 | 自动化流程收到空回复不推进状态，有限重试后升级 |

## 4. 生命周期

| 规则 | 说明 |
|------|------|
| 优雅停机 | 收到停止信号：停止接新任务 → 处理中任务限时完成 → 释放资源 |
| 健康检查 | `/health` 返回依赖状态；就绪/存活分离 |
| 启动顺序 | 依赖未就绪时重试而非崩溃（有上限） |
| 数据持久化 | 关键状态落盘/落库；内存态需说明丢失影响 |

## 5. 外部依赖韧性（实测教训）

> 来源：2026-10-05 一次真实排障——外部网关对**连续/超大请求**直接断开连接，而重试逻辑
> 只认错误码、分片逻辑没有上限粒度、失败整链抛错，三个缺陷叠加导致功能完全不可用。
> 定位过程见 [troubleshooting.md](troubleshooting.md)。

| 规则 | 说明 |
|------|------|
| **传输层错误 = 网络错误** | 只按错误码判断可重试会漏掉最常见的失败形态：`fetch TypeError` / `ECONNRESET` / `socket hang up` / `terminated`（真因常埋在 `cause` 链里）。可重试判定必须覆盖传输层，不能只查业务错误码。 |
| **限流可能表现为断连** | 被依赖方限流时不一定回 429，可能直接重置连接。因此"重试 + 退避"之外还要有**调用间隔**（连续调用之间主动等待）；否则重试本身会持续撞墙。 |
| **请求粒度必须有界** | 单条消息/单个请求体不得无界增长。日志、工具输出、历史拼接都设上限并切分；"总量不大"不等于"单条不大"。 |
| **自适应缩小重试** | 失败后不要原样重试：能缩小就缩小（对半切分输入、降低批量），把大请求逐步降到被依赖方接受的粒度。只重试不缩小的重试，多数是浪费配额。 |
| **批量任务降级不炸链** | 分片/批处理中，单段失败应标记并继续（保留原始数据可回查），而不是让整个任务失败。最终结果允许是"部分摘要 + 明确缺口标记"。 |
| **安全阀不得被降级绕过** | 调用次数上限、最大片数、最大轮数这类**防失控阀**必须保持致命（超限即失败），不能纳入"降级继续"的范围——否则失控时不会停。 |
| **空响应要区分语义** | "空输出"可能是被依赖方正常应答了空内容、也可能是预算被隐藏推理吃光。区分手段：看结束原因（`finish_reason`/`stop_reason`）与用量字段，而不是只看内容长度。 |

## 6. 验证清单

- [ ] 每个外部调用有超时配置
- [ ] 关键写操作幂等或 CAS
- [ ] 重试有上限和退避
- [ ] **可重试判定覆盖传输层错误（含 `cause` 链），不只按错误码**
- [ ] **连续调用有间隔/限速，重试带退避**
- [ ] **单条消息/单请求体有大小上限，超限切分**
- [ ] **批处理单段失败可降级继续，且安全阀（次数/片数/轮数）仍致命**
- [ ] 异常路径有测试（超时/重试耗尽/依赖故障）
- [ ] 消息处理有去重与死信策略
- [ ] 状态机无死循环（有兜底/升级路径）
- [ ] 服务可优雅停机（测试 SIGTERM）
